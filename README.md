# FREE FLOW — 一口自由

GitHub Pages 目前從 `publish-pages` 分支根目錄發布，更新 `index.html` 並推送到此分支後會自動重新部署。支援具備 Canvas `roundRect` 與現代 JavaScript API 的新版桌面及手機瀏覽器。

Faust Game Jam 單鍵玩法 prototype 11。從肺部一路經過氣管、咽喉到鼻腔，用呼吸將黃色異物排出。地圖高 7,000 單位，超過七個標準鏡頭高度，肺部與鼻腔會拉遠鏡頭顯示構造；鏡頭跟隨異物，右側小地圖保留完整旅程。

直接用瀏覽器開啟 `index.html`，不需安裝套件或連線。也可以執行 `python3 -m http.server 8765 --bind 127.0.0.1`，開啟 http://127.0.0.1:8765。

現在可按「雙異物」或直接開啟 [雙異物短關卡](http://127.0.0.1:8765/?v=11&duo)。固定鏡頭同時顯示兩者，不用追著其中一個移動；原本完整旅程與吸氣練習仍可切換。

兩個異物的關卡設計參考：

- [Binaries — Ant Workshop 官方介紹](https://binaries.ant-workshop.com/)：玩家同時控制兩顆球，同一組操作要兼顧兩條路上的危險。此 prototype 採用共同輸入、不同位置的原則，另外加入異物彼此的實體碰撞。
- [Puddle — Nintendo／發行商介紹](https://www.nintendo.com/en-gb/Games/Wii-U-download-software/Puddle--676979.html)：藉由傾斜環境引導流體，各種流體特性不同，障礙與環境影響結果。這裡借用全局操作搭配物體特性與地形的設計原則，控制的是共同呼吸氣流。

以下關卡安排是本 prototype 的設計推論：黃異物維持原有不規則輪廓，質量設為 1；粉異物縮為 0.62 倍，質量為 0.25。兩者共用氣流，阻力加速度按尺寸平方／質量調整，因此小異物對換氣反應更快，並非給它額外的指定移動。重力加速度相同，轉動仍來自碰撞與角速度，不設定目標朝向。

下方肺部以支氣管分隔成兩條起始通路，中段匯流並繞過偏心斜坡，再通過 35 單位寬的喉頭窄口；上方兩片鼻甲交錯；出口前還有鼻咽軟瓣，需要主動吸氣 0.45–1.4 秒再吐氣才能開啟，開口保留 2.3 秒。耗盡後的強制深吸超過這段區間，因此無法一直按住自動通關。出口需要整個異物輪廓越過。匯流後可能互相頂住，吸氣可使兩者退開、碰撞換角；細小的異物容易通過窄縫，但也更容易被吸回。右側有實體魚刺尖端，持續刺碰三次或任一異物掉回肺底，兩者一起重試。沒有倒數計時。

兩個都排出才成功，HUD 顯示 `0 / 2`、`1 / 2`、`2 / 2`。先排出的異物退出物理模擬，不再被吸回；重試保留雙異物模式，「完整關卡」回到原本長關卡。「雙異物」按鈕也可隨時重置此段。

`duoShapes` 定義固定地形，`duoSolids()` 加入呼吸軟瓣的即時開口；它們是畫面、實體碰撞與粒子遮擋共用的短關卡幾何。`duoStream()`／`duoVelocity()` 依分流、匯流與鼻甲彎道提供同一解析流場，仍是遊戲近似。`pairManifold()` 用兩個旋轉後的實際凸多邊形做分離軸檢查，裁切接觸區域；`collidePair()` 按質量、轉動慣量和接觸力臂分配法向與摩擦脈衝，位置修正按逆質量分攤。靜態腔壁沿用原有剛體接觸解算，使用個別尺寸的轉動慣量。每步以 16 次迭代處理擠在一起的多點接觸，最後再檢查靜態地形；驗證的通關路線雙輪廓未穿入地形，異物間最大殘餘重疊低於 0.05 世界單位。

已用鍵盤吸吐事件驗證一條約 17.0 秒的雙異物通關路線，未修改角色位置或朝向：吐 2 秒、吸 2.4 秒、吐 2 秒、吸 2.4 秒、吐 2 秒、吸 2.4 秒，再吐 2 秒、吸 0.8 秒打開出口軟瓣，再吐到兩個排出。這是可重現的測試路線，不是唯一解；持續吐氣 6.1 秒會在共同窄口卡住，且尚未觸發自動深吸；持續按住 60 秒，反覆自動深吸仍無法越過出口軟瓣。物理接觸對時機敏感，玩家可多次退回寬腔調整。

- 按住空白鍵或畫面上的按鈕：吐氣，增加往出口的氣壓並消耗氣量。
- 放開：用約 2.4 秒吸滿一口。補氣從慢到快，接近滿氣時再減速；吸入氣流強弱跟著補氣速度變化，隨時按住可中斷普通吸氣。異物先靠慣性前進，再受到空氣阻力與重力減速。
- 氣量耗盡到 0%：強制深吸氣約 1.8 秒，途中按住、放開或重新按下都無法中斷，吸入氣流比普通吸氣強。吸滿後，如果仍按住就恢復吐氣；已放開則回到輕柔呼吸。耗盡不直接位移異物，退回仍由同一氣流、阻力與重力產生。
- 普通吸滿後，放開狀態會自然吐出少量氣，再吸回來：自然吐氣約 2.6 秒、吸氣約 2.4 秒，氣量在 88%–100% 間循環，氣流很弱。主動吐氣可隨時接手；短促反覆點按不能立即補滿氣量。
- 異物是實際參與碰撞的不對稱七邊形，橫向約 46、縱向約 31 單位。撞擊邊角會翻轉，擦牆會滑動；同一個窄縫，轉到窄的一面可能就能通過。呼吸改變撞擊速度與時機，不直接控制角度。
- 從下方撞上一般較水平牆面（朝腔內法線的向下分量大於 0.7）時，強碰撞的回彈係數調為 0.9。反彈後 0.35 秒內，只把沿碰撞法線、會將異物再壓回牆上的空氣阻力降到 12%，其餘方向、重力與碰撞轉動正常計算。這是遊戲手感調校，避免反彈馬上被持續吐氣抵消；沒有最低彈出速度、直接位移或指定角度。魚刺保留原有材料反應。
- 腔壁有回彈與撞擊波紋；普通軟組織較能吸收撞擊。低速接觸不回彈，避免在壁面反覆抖動。
- 三處橫向魚刺有實體尖端與倒鉤，碰到任何部位都增加喉嚨刺激。每次增加 34，第三次達到 100 即失敗；0.9 秒受傷冷卻避免同一幀碰撞重複扣分，但持續磨蹭仍會再次受傷。
- 掉回肺部底端也會失敗。短吐氣維持高度，短吸氣減速並補氣，沿流線繞過魚刺；普通組織碰撞會反彈，不增加刺激。
- 氣管上端加入 35 單位寬的喉頭窄口，下方是較寬的腔室與偏心軟骨斜坡。異物橫放時可能被兩側卡住，吸氣可拉離接觸點、退到斜坡碰撞換角，再吐氣通過；窄口不會因吸氣或計時自動打開，已轉到窄面也可能直接通過。
- 按「吸氣練習」或開啟 http://127.0.0.1:8765/?v=11&practice，可直接從窄口下方開始。先吐氣約兩秒，卡住後放開，吸到異物退回並碰上斜坡，再吐氣；觀察碰撞換角，不需精準計秒。突破窄口即完成練習，「再呼吸一次」重試同一段，「完整關卡」回到肺部。練習不修改碰撞輪廓或替玩家轉動異物。
- 喉頭有軟骨外框與成對聲帶，聲門定時收合；白色聲帶邊緣的碰撞形狀跟著開口變化，需觀察開口再前進。
- 咽喉旁分出向下的食道，內側有縱向皺褶與吞嚥收縮的動畫。異物可由岔口滑入，進入深處後被吞下去，判定失敗。食道沒有呼吸氣流，留在有流線的主氣道才會往鼻腔前進。
- 咽喉薄膜與鼻咽軟組織需要不同長度的吸氣。吸到畫面上的綠色區間，立刻吐氣，開口會短暫保留；吸過頭則再次閉合。
- 鼻腔由鼻中隔分成兩條通路；兩側外壁長出上／中／下鼻甲，輪廓捲曲、覆有厚黏膜與淺色骨質內芯。沿鼻甲和鼻中隔間的狹窄鼻道前進，下鼻甲較厚，上鼻甲較小。
- 最上方的鼻腔出口即終點；沒有倒數計時，可隨時重新開始。失敗會停止物理模擬，重試清除刺激與進度。

共十二處主要障礙：三處魚刺、五處軟瓣／鼻甲、一處喉頭窄口、一處定時聲帶、兩處依呼吸開合的薄膜；另外有參與碰撞的肺部分隔、鼻中隔與食道岔路。魚刺、聲帶與薄膜需要不同呼吸節奏。

| 肺部 | 成簇肺泡、兩側腔室與 Y 形支氣管匯流 | 從左側出發、沿氣道匯流；右側腔室有局部回流，匯流口有魚刺，掉回肺底失敗 |
| 氣管 | 較直的窄管、規律軟骨環、喉頭外框與成對聲帶 | 氣流較快；避開倒鉤魚刺，吸氣退回寬腔、借斜坡換角通過窄口，再等待兩片聲帶之間的聲門打開 |
| 咽喉 | 較寬的腔室、會厭與軟顎葉片、向下延伸的食道支路 | 換氣繞行、觀察薄膜開口、避開第三處魚刺；誤入食道會被吞下去 |

美術採用參考圖的高彩度貼紙卡通方向：深紫氣道和陰影、亮黃角色與按鈕、桃紅和青藍吸吐狀態，器官使用珊瑚粉肺部、青藍氣管、桃紅咽喉與橘黃鼻腔。外框、腔壁、聲帶、鼻甲和異物加入白色貼紙邊與粗紫描線，肺泡用高光泡泡、軟骨環用青綠弧圈，食道保留深紫腔室和桃紅皺褶。魚刺用白色骨架與粉紅尖端，吐氣軌跡亮黃、吸氣軌跡青藍；介面使用紫色卡片、圓角粗字和實色陰影。

`art` 定義共用描線、白邊與角色／氣流色；`regions[].color` 定義四個器官色，CSS `:root` 管理介面色。`stickerShape()` 直接使用原有多邊形繪圖，角色表情和白色描邊均為裝飾，不改變碰撞輪廓。所有素材仍為原生 Canvas／CSS，沒有外部字型、圖片或新增套件。

畫面、地形與碰撞皆由原生 Canvas / JavaScript 產生。`profiles` 定義通道輪廓；`obstacles` 定義障礙位置、側面缺口和薄膜的吸氣區間。`structures`、`shelfShape()`、`fishbonePieces()`、`neckShapes()` 與 `vocalShapes()` 的多邊形由繪圖和碰撞共用。`branchEdge` 定義食道的實體邊界，`rightOutline` 把它接入主氣道輪廓；`inAirway()` 檢查兩條路的聯集，粒子遮擋也採用同一幾何。`prick()` 管理魚刺刺激與冷卻，`fail()` 管理三種失敗。鏡頭高度會依部位平滑縮放；標準鏡頭高度 `VIEW` 與地圖高度 `H` 分開。

氣流使用遊戲用的解析流場近似：`channel()` 依分岔與缺口彎曲，`stream()` 加入障礙附近的渦流與肺部局部回流，`velocityAt()` 從流函數求出水平／垂直速度，再乘上平滑變化的呼吸氣壓。整體吐氣仍流向出口，但局部可橫向、彎曲甚至向下。`step()` 用相對氣流的阻力加速異物，保留慣性與重力；吸氣不直接改寫位置或指定橫移。粒子使用同一流場，保留軌跡，途中遇到實體會重新生成，避免穿過薄魚刺。這是可調整的遊戲近似，沒有求解完整流體方程。

`breathe()` 管理主動吐氣、普通吸氣、強制深吸與自然吐氣四個階段。吸入氣量使用半餘弦曲線 `(1-cos(πt))/2`，因此開始和結束時慢、中段快；由當次氣量變化求出吸入氣流強度，再平滑送入流場。強制深吸會暫時覆蓋輸入，但保留按鍵／觸控的實際按住狀態。聲門提示、薄膜吸氣計時與 HUD 都讀取實際呼吸階段，不會把「仍按住但正在強制吸氣」當作吐氣。時間、氣量與力道均為遊戲調校，氣量百分比表示可用吐氣量；0% 深吸是玩法規則，並非人體肺容量或反射的量測模型。

碰撞改為平面剛體近似。`outline` 同時用於繪圖與接觸判定，先以多邊形面積求質心和轉動慣量；`bodyPoints()` 把輪廓依 `body.angle` 旋轉到世界座標。`segmentHitsBody()` 檢查邊線相交，`support()` 找出接觸方向最突出的角或面，`resolve()` 根據接觸點的線速度加旋轉速度，施加法向回彈與受限的切向摩擦脈衝；偏離質心的撞擊會改變 `body.omega`。位置修正與速度脈衝分開：發生穿入時，依實際接觸力臂與轉動慣量修正角度，再沿法向移出剩餘穿入量，避免窄縫裡略微嵌入壁面就滑過。已分離的接觸不再次反彈，每次物理更新迭代五次處理多點接觸。自由飛行的角度只由角速度推進，空氣逐漸阻尼；沒有目標朝向、自動轉正或依移動速度播放的裝飾旋轉。

喉頭窄口與軟骨斜坡使用同一組固定多邊形供繪圖、碰撞與粒子遮擋；一般方向回彈係數 0.28、摩擦 0.45；向下法線的強撞擊套用上方牆底回彈規則。斜坡碰撞透過接觸力矩改變角速度，沒有目標朝向或強制轉正。

除上述一般牆底的強撞擊外，腔壁回彈係數 0.58、摩擦 0.12；魚刺 0.42／0.25，軟瓣與鼻甲 0.38／0.22，聲帶 0.25／0.20。接觸速度小於 28 單位／秒時不回彈；超過 55 時腔壁會顯示短暫波紋。腔壁仍保留固定幾何，彈性透過回彈係數呈現。`wallBounds()`、繪圖和碰撞共用每 5 單位取樣的壁面，避免光滑曲線和碰撞線段的微小差異。原本依固定圓半徑限制聲門的修正已移除，開口提示也會參考異物目前朝向的寬度。
